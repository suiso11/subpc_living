# Continuous Conversation Loop

## 目的

自発会話を「利用回数を増やす通知」ではなく、ユーザーが話したいときに
対話を1段深め、次回も文脈を失わない小さなループとして扱う。

設計原則:

- 通知数より、返信後の会話品質を優先する。
- 無視は拒絶ではなく「今はタイミングではない」と解釈する。
- 罪悪感、連続利用記録、過度なプロファイリングは使わない。
- 後回し・当日停止・無期限停止を、いつでもユーザーが選べる。

## 状態遷移

```text
eligible
  └─ 質問送信 → pending
                    ├─ 返信 → engaged → 当日上限
                    ├─ あとで → snoozed
                    ├─ 今日は静かに → snoozed-until-tomorrow
                    └─ 期限切れ → ignored → 2倍バックオフ

any state
  ├─ 自発会話を停止 → paused
  └─ 自発会話を再開 → eligible
```

## ケイデンス

- ユーザー活動から規定のアイドル時間後にのみ候補となる。
- 既定は1日1件まで。
- 返信待ち中は次の質問を送らない。
- 返信期限を過ぎると、次回の最短間隔を `base × 2^ignored_streak` にする。
- バックオフは既定で72時間を上限とする。返信があれば0に戻る。
- quiet hours 内は送信しない。

## 返信後の対話

返信があった場合は送信済み質問を会話文脈に復元し、LLMに次を求める。

1. ユーザーの内容をまず受け止める。
2. 話す意欲が見える場合だけ、掘り下げ質問を1つまで返す。
3. 断りや話題変更には質問を返さない。
4. センシティブな属性を推測しない。

以降は通常のチャンネルセッションが文脈を保つため、ユーザーが続ける限り
自然な議論を続けられる。

## 永続化とプライバシー

`data/proactive/conversation_state.json` に保存するのは、送信済み質問、
送信・返信時刻、カウンタ、スヌーズ、停止状態だけである。
ユーザーの返答本文はこの状態ファイルに重複保存しない。
書き込みは一時ファイルから `os.replace` する。壊れたJSONはBotを停止させず、
`state_error` として `/status` から確認できる。

## 意図的に含めないもの

- 連続日数、ポイント、バッジなどの習慣化ギミック。
- 返信を催促する再通知。
- 生の返答本文を別テーブルへ保存すること。
- 自発質問の音声読み上げ。明示的に有効化した場合だけ読み上げる。
